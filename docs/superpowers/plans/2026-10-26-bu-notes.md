# BU Notes Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A staff-only "Notes" tab on Business Unit Edit, behaving exactly like Cluster Notes (plain-text notes, attachments, files panel, edit history, soft delete with restore) but fully separate: own table, own permissions (`bu_note.view` / `bu_note.manage`), never shown on the cluster page and vice versa.

**Architecture:** New `tb_business_unit_note` table (backstage schema), new `business-unit-note` module in micro-cluster (RPC service `business-unit-notes`) built on a NEW shared helper file — the `cluster-note` module is not touched. New gateway module `api-system/business-units/:businessUnitId/notes` gates every route with `BackstagePermissionGuard` + literal `bu_note.*`, then resolves the BU's `cluster_id` through a thin RPC (`business-unit-notes.owner-cluster`) and checks the grant covers that cluster, before any notes RPC. History is served by the notes module; generic `activity-logs` refuse `business_unit_note` rows. FE makes the notes components owner-agnostic (service adapter + permission-key props), the cluster page keeps its behaviour, and BU Edit gets a sixth tab.

**Tech Stack:** NestJS microservices + Prisma (backstage schema) + MinIO via micro-file RPC; React + TS + shadcn/ui + Tailwind (Vite, Bun).

**Spec:** `docs/superpowers/specs/2026-10-26-bu-notes-design.md` (in carmen-backstage). Read it, and `2026-10-26-cluster-notes-design.md`, before any task. Template implementation: branch `feature/cluster-notes` in both repos.

## Global Constraints

- **Test steps are skipped by user preference** — do not create `*.spec.ts` / `*.test.ts(x)`. Still run type-check, lint and the backend gates. Existing suites must stay green.
- Two repos, one branch each, named **`feature/bu-notes`** in both `carmen-turborepo-backend` and `carmen-backstage`, each created from the current `feature/cluster-notes` head of that repo. Never commit to `main`. Subagents must be told the branch name explicitly.
- **Do not push the backend branch until Task 5, and only after the controller confirms** — pushing a branch that carries a migration has applied it to DEV within ~2 minutes before.
- **Do not modify the backend `cluster-note` module** (micro `src/cluster/cluster-note/`, gateway `backstage_cluster-notes/`). The BU module uses a new helper file; moving cluster-note onto it is a recorded follow-up debt. The only shared files touched are the registry, `HIDDEN_ENTITY_TYPES`, `activity-log-scope.ts` (type widening), seeds, catalog.
- Notes and files are visible to backstage staff only. `tb_cluster_user` membership / cluster admin and `tb_user_tb_business_unit` users must never grant anything. Gate with `BackstagePermissionGuard` + `@RequireBackstagePermission('<literal>')` then a fine-scope check — **never** `readableClusterScope()` or anything membership-based.
- Permission keys are string literals in decorators (`audit:api-system-permission` does not resolve constants). `bu_note.*` and `cluster_note.*` are independent: neither implies the other.
- Fine scope: resolve the BU's current `cluster_id` first (BU missing or soft-deleted → 404), then `resolveAllowedClusterIds(eff, 'bu_note.view' | 'bu_note.manage')` must cover it. Done before every notes RPC, including when the grant is unrestricted (`null`).
- Files: PDF, jpg/png, doc/docx, xls/xlsx; ≤ 10 MB each; ≤ 5 per request.
- Message: plain text; a note needs a non-blank message or ≥ 1 attachment.
- List page size 20, newest first; deleted list ordered by `deleted_at` desc.
- Never delete from MinIO. Removed attachments stay in JSONB with `removed_at`.
- Never store or return presigned URLs in note payloads; URLs only from `POST files/url` (body `{ fileToken }`, never in the path).
- `bu_note.manage` is only honoured together with `bu_note.view`.
- Deleted notes are read-only until restored; no hard delete.
- Notes of a soft-deleted BU are unreachable (404) until the BU is restored; a BU that moves cluster is scoped by its current cluster.
- Backend lint: `bunx eslint <path>` from inside each app dir — **never `bun run lint`** (it runs `--fix` over the whole repo).
- FE: `doc_version` via `src/utils/docVersion.ts`; errors via `utils/errorParser.ts`; `toast.*`; `ConfirmDialog` for delete; TH + EN strings. Cluster-notes UI strings (`pages.clusterNotes.*`) are reused as-is by the BU tab (no copy changes).

## Review Focus

1. **A `cluster_note`-only holder reaching BU notes, or a `bu_note`-only holder reaching cluster notes** — literals in decorators, `assertCanManage`, FE permission keys, and the refactored components must never fall back to the other family. Curl matrix in Task 9.
2. **Customer-side access** — a customer BU user (`tb_user_tb_business_unit`) or cluster admin (`tb_cluster_user`) with no backstage role must get 403 on every BU notes route, `files/url`, and `activity-logs/record/:id` / `:id/detail` for `business_unit_note` rows. Tasks 3, 4, 9.
3. **A cluster-scoped `bu_note.*` grant for cluster A reaching a BU in cluster B** — the guard is coarse (any cluster); the controller must check the BU's own `cluster_id` via owner-cluster, before notes RPCs. Task 4 + Task 9.
4. **A `fileToken` from another BU (or from a cluster note) passed to this BU's `files/url`** — must 404, never sign. Task 2 `ownsFile` scoped by `business_unit_id` + Task 9.
5. **Cluster-notes regression after the FE refactor** — same tab, count, composer, edit/409, files panel, deleted list, history, 390px, TH/EN. Task 6 (static) + Task 8 (browser).
